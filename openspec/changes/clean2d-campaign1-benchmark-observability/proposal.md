# Proposal: Build Clean2D Benchmark and Observability Foundation

## Why

The master Clean2D campaign policy requires a reproducible benchmark before algorithmic changes. The repository already has test-owned regression cases, geometry metrics, debug snapshots, baseline reports, deterministic comparison, and diff review, but Campaign 1 needs one explicit metadata contract and one reproducible execution surface that can explain families, topology, candidate evidence, runtime, and controlled outcomes.

## What Changes

- Add a Campaign 1 OpenSpec for benchmark and observability.
- Extend the test-owned regression case metadata with stable size class and derived topology metadata.
- Extend the existing test-owned baseline report with an observational metric vector, candidate evidence, and runtime evidence.
- Keep baseline writing, comparison, and review deterministic and JSON-serializable.
- Add focused tests and a machine-readable Campaign 1 evidence report fixture generated by the existing developer runner.

## Scope

This campaign changes only test-owned regression infrastructure, the developer baseline-report script, Campaign 1 documentation/contracts, and tests. It does not change production Clean2D algorithms, routing, ranking, GUI behavior, persistence, chemistry, or module boundaries.

## Non-goals

- No layout or candidate-selection improvement.
- No new production metric thresholds.
- No molecule-specific routing.
- No new external dependency.
- No visual GUI validation; that remains a later manual acceptance activity.

## Success criteria

- The Campaign 1 OpenSpec validates strictly.
- Every corpus case has stable identity, size class, family tags, and reproducible derived topology metadata.
- Baseline records expose a complete diagnostic-only metric vector with explicit unavailable values where a metric is not computable.
- Repeated baseline runs are equivalent apart from documented ephemeral fields.
- The CLI can write, compare, and review reports with stable exit codes and JSON output.
- Existing production Clean2D behavior remains unchanged.
