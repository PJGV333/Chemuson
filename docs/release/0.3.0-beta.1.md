## Limitaciones y advertencias

- **P1 — iconos:** el propietario reportó la ausencia en el primer preview (#37826597134) y después informó que los iconos se recuperaron en una comprobación de un segundo preview, en Windows portable y AppImage, ambos temas. Ese registro no identifica el run/SHA/entorno ni adjunta captura, así que no puede reemplazar el estado histórico `FAILED` ni probar el preview actual. Los gates de iconos congelados pasan en #38677446246; el retest visual de los artifacts actuales sigue pendiente y bloquea beta según la matriz.
- **P1 — ChemName:** los CArchive Windows/AppImage del Preview `37855524295` tenían cero templates `.mol`; no se modificaron reglas de nomenclatura. El Build Preview actual #38677446246, SHA `de881d2d31e45b434169bc971222bfec49e1dc07`, pasó 9/9 templates y 6/6 controles de nombre comparados con Python en Windows portable, AppImage y Flatpak `/app`. Los retests manuales de barra de estado/anotación y los nombres sobre los artifacts exactos siguen pendientes.

- **Molecular Assistant es experimental.** La salida de un modelo requiere revisión química. Una cadena SMILES válida no demuestra por sí sola que la identidad solicitada sea correcta. Disponibilidad, configuración del proveedor y calidad de respuesta dependen de servicios externos; la matriz registra por separado validez, procedencia e identidad.
- **UI-ONBOARDING-001 — retest pendiente.** En el segundo Build Preview el propietario observó el onboarding desalineado en Windows portable. La fuente difiere su creación hasta después del primer layout visible y recalcula el spotlight en resize/move/cambio de pantalla; el tercer paso resalta el menú visible de Ver y el SidePanel permanece cerrado hasta que el usuario lo abra. Se conservan los tres pasos y la preferencia existente. Las pruebas Qt no sustituyen el retest en el nuevo paquete Windows (y comprobación de consistencia Linux): sigue `NOT TESTED — owner retest required`.
- **BRANDING-001 — retest pendiente.** Las superficies de presentación usan `ChemUSON`. Acerca de debe mostrar `ChemUSON es un editor molecular libre y de código abierto para crear, editar, visualizar y analizar estructuras químicas, diagramas y anotaciones científicas.`; el título principal es `ChemUSON 0.3.0-beta.1 — Editor Molecular Libre`. No se han inspeccionado aún estos textos en los nuevos paquetes; sigue `NOT TESTED — owner retest required`.
- **P1 — RDKit isolated backend unavailable in packaged executable.** El fallo manual histórico de Windows portable se reprodujo como despacho incompatible del worker congelado; no era una regla química. En #38677446246, Windows portable y AppImage pasan imports nativos dentro del bundle, etanol (logP -0.0014, TPSA 20.23, HBD/HBA 1), SMILES y worker 3D aislado. El retest GUI del propietario en esos artifacts exactos sigue pendiente; bloquea beta según la matriz.
- **Estado del harness Qt y crash de producto:** el callback de test de drag se desconecta en `finally`; además, la selección falsa en el shard se debió a modificadores Ctrl sintéticos retenidos por tests previos. El test ahora libera Ctrl/Shift/Alt/Meta y verifica `NoModifier`; CI #38677446364 pasa 8/8 shards. Esto no demuestra que el SIGSEGV reportado por el propietario en el AppImage esté resuelto: el retest de cierres instalados/paquetizados (`START-05/06`) sigue pendiente y no se atribuye el crash de producto al harness.
- **Linux portable:** el preview actual #38677446246 es AppImage Type 2 real (`AI\x02`). El validator del job pasó extracción, iconos claro/oscuro/HiDPI, RDKit, ChemName y headless launch. Además, el artefacto descargado se extrajo localmente sin FUSE; AppRun, desktop, SVG, AppStream y binario están presentes y `usr/bin/Chemuson --version` devolvió `0.3.0-beta.1`. No es aceptación gráfica manual. El intento local del validator completo no pudo inspeccionar el CArchive porque PyInstaller no está instalado en este entorno; el job remoto sí ejecutó y aprobó ese validator completo.
- Los cuatro paquetes actuales se construyeron en #38677446246 para SHA exacto `de881d2d31e45b434169bc971222bfec49e1dc07`; se descargaron y verificaron los hashes y provenance. El instalador se generó desde el portable validado, pero no se instaló manualmente. No sustituyen el retest propietario ni autorizan release/tag/canales públicos.
### Limitaciones conocidas aceptadas (no son defectos bloqueantes por sí mismas)

- **ChemName/IUPAC:** no posee cobertura general garantizada. Los casos no verificados no se presentan como exactitud IUPAC universal; las disputas requieren una estructura exacta y referencias actuales.
- **Clean2D:** conserva limitaciones para geometrías complejas. Esta microcampaña no altera ni certifica heurísticas de dibujo.
- **Molecular Assistant:** es experimental; toda propuesta requiere revisión y una cadena SMILES válida no demuestra identidad solicitada.
- **Predicciones espectrales:** son estimaciones heurísticas y no sustituyen medidas experimentales.
- **Teardown Qt:** que un cierre concreto termine correctamente no certifica todos los escenarios de teardown Qt. En esta campaña dos probes fuente/offscreen acotados cerraron la ventana con `async_shutdown_complete=True`, pero el proceso terminó con SIGSEGV 139 durante el teardown del intérprete Qt; el segundo añadió limpieza explícita del UndoStack y `processEvents()` tras el cierre. El shard pytest focalizado de splitter/hide/show sí pasó. No se atribuye causa ni se presenta como crash del paquete, y los fallos de harness/orden se registran aparte.

### Mejoras futuras

- La cobertura general de ChemName/IUPAC y las geometrías complejas de Clean2D requieren campañas independientes con sus propios contratos y evidencia. No son alcance de este pulido de interfaz.
- Clean2D, las reglas químicas y la serialización `.cmsn` no se modifican aquí. Los casos de aceptación detectan regresiones; no amplían ni certifican todas las heurísticas.
- Authenticode, HMAC y firma GPG dependen de secrets/configuración protegidos; no asumir que un paquete está firmado si la ejecución no lo acredita.

## Antes de cualquier publicación

1. Revisar SHA y procedencia de los cuatro artifacts de Actions.
2. Ejecutar y registrar casos de aceptación en Windows y Linux, incluyendo instalación/actualización, cierre, persistencia y datos químicos.
3. Resolver o aceptar explícitamente cada fallo y deuda; P0/P1 atribuible bloquea stable.
4. Completar los casos P0/P1 pendientes sobre los artifacts exactos (incluidos datos, cierre/crash, worker RDKit, ChemName e instalación del setup), verificar la protección externa `v*`/environments —la API de rulesets devolvió una lista vacía en esta revisión— y obtener autorización final explícita. Sólo después considerar el tag protegido `v0.3.0-beta.1`.
