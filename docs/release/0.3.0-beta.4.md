# ChemUSON 0.3.0-beta.4 — registro interno de preparación

Esta página acompaña a [las notas públicas](0.3.0-beta.4-public.md). La evidencia completa, baseline y tareas están en [OpenSpec `prepare-chemuson-0-3-0-beta-4`](../../openspec/changes/prepare-chemuson-0-3-0-beta-4/).

## Alcance

Preparar el nuevo logo aprobado, reconocimiento de autoría, documentación y metadatos, corrección AppImageUpdate, limpieza segura y cuatro paquetes preview sin modificar la funcionalidad científica de beta.3.

## Clasificación excepcional de beta.3

La API pública de GitHub consultada el 2026-10-26 confirmó que `v0.3.0-beta.3` tiene `prerelease=false`, `draft=false`, y que `/releases/latest` devuelve beta.3. El propietario tomó manualmente esta decisión excepcional; no debe extrapolarse a otras betas. La fuente canónica del tag sigue siendo SemVer beta.

## Hallazgo y corrección de AppImageUpdate

El AppImage beta.3 publicado conserva:

```text
gh-releases-zsync|PJGV333|Chemuson|prerelease|Chemuson-v0.3.0-beta.3-linux-x86_64.AppImage.zsync
```

El código upstream de AppImageUpdate revisado en `AppImageCommunity/AppImageUpdate` commit `a211784dfc746fdb6d8d32d6bb39add451c1ddeb` trata `latest`, `latest-pre` y `latest-all` como selectores especiales; todo otro valor se usa literalmente en `/releases/tags/<valor>`. Por tanto, `prerelease` no consulta una lista de prereleases y beta.3 no puede actualizarse mediante ese metadato. La versión beta.3 ya publicada no se reconstruye ni modifica.

Los paquetes estables nuevos usan `latest`; los beta, `latest-all`, que elige la release más reciente independientemente de su booleano GitHub y permite graduación a estable. Beta.3 queda con actualización AppImage manual a beta.4. `appimageupdatetool` no está instalado en el entorno local, así que la inspección del upstream es estática y no se afirma una actualización dinámica PASS.

El updater integrado de ChemUSON es distinto: toma identidad y precedencia del tag SemVer, filtra `stable`/`beta` desde la versión y preserva settings, guardas de downgrade y checksum. Esta campaña no cambia las preferencias persistidas.

## Versionado y clasificación futura

La versión canónica candidata y AppStream se preparan para `0.3.0-beta.4`. `.github/workflows/release.yml` deriva `prerelease=true` del canal beta; no cambiar el metadato para forzar **Latest**. Si GitHub conserva el distintivo en beta.3, beta.4 seguirá enlazándose por su propia Release una vez publicada.

## Artefactos históricos

Se preservan tags/releases existentes y los dos manifests trackeados de `dist-appimage-diagnostic/`. Las carpetas ignored de builds locales se clasificaron en el baseline OpenSpec y se limpiarán selectivamente; no utilizar `git clean -fdX`.

## Publicación

No crear `v0.3.0-beta.4` ni GitHub Release antes de la aceptación explícita del propietario. Los artifacts de Build Preview no son assets oficiales y requieren verificación de checksums/provenance desde el SHA único candidato.
