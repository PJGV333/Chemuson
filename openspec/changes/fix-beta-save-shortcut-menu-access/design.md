# Diseño

1. La baseline de `baseline.md` reproduce que `action_save` no recibe Ctrl+S/Ctrl+G en modo compacto y que el guardado original sí serializa el documento. Qt confirma la causa: el `QAction` sólo queda alcanzable desde superficies ocultas. Registrar el mismo objeto también en la ventana habilita su `WindowShortcut`; no crear `QShortcut`, señal ni handler paralelo.
2. Conservar `FileController.save_file` como ruta única. Guardar usa el canvas activo que expone el contexto existente; la persistencia nativa sigue `.cmsn`. Un archivo asociado `.cmsn` actualiza su ruta sin diálogo; documento sin ruta pide una nueva. La ruta y el `QUndoStack` sólo se limpian tras éxito. `.mol` sigue siendo exportación de estructura separada.
3. El cierre mantiene `DocumentController.confirm_discard_changes` y `CanvasTabManager`: Save autoriza cierre sólo si el canvas objetivo quedó clean; Discard lo cierra tras la respuesta explícita; Cancel, diálogo cancelado o fallo de persistencia conserva la pestaña y sus datos. Para una pestaña no activa se prueba la activación temporal y restauración del documento activo.
4. `MainWindowUiBuilder` añade una única QAction checkable **Mostrar barra de menús** al menú Ver. La ventana alterna la visibilidad de su `QMenuBar` original; no construye una segunda barra/menús. El modo compacto sigue abriendo el agregador/hamburguesa existente.
5. Extender `UiPreferences`/`load_ui_preferences`/`save_ui_preferences` con una preferencia booleana UI (por defecto compacto) bajo una clave `ui/*` estable. La preferencia se aplica durante shell assembly y no se pierde al persistir cambios de tema.
6. Pruebas Qt con `QTest`, `QSettings` aislado y `tmp_path` comprobarán atajo, acción de menú, JSON CMSN real, documentos múltiples, cierre, preferencia reiniciada y ambos modos con tema claro/oscuro y tamaños distintos. Los gates serán acotados externamente a ≤10 minutos por invocación.
